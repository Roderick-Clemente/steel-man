## Cause, per seat

**grok-4.5 — orchestrator error.** The invocation carried
`--enabled-tools Read,Glob,Grep,LS,Execute` but no `--auto` flag, so droid ran at
its default read-only tier. The reviewer requested a command the tier refused and
the CLI aborted the whole session rather than degrading. The prompt had
deliberately closed the Phase 1 round 1 hole by putting `Execute` in the
allowlist; it left the adjacent hole open. **`Execute` permitted in the tool list
is necessary and not sufficient — the autonomy tier must also allow it.**

**gemini-3.1-pro-preview — model-side, unexplained.**
`LLM response contained no usable output` from `agent_loop`, then `Exec failed`.
Not an autonomy refusal; the tier never came up. 127695 bytes across 18 events
means it worked (6 tool calls, 6 results, 2 reasoning blocks) and then returned
nothing usable. Root cause not established. Do not assume the `--auto` fix
addresses this seat; re-fire is the only way to find out, and if it recurs the
seat should be swapped.

## Why the byte counts are in this file at all

The fire script printed `154293 total` and both sha256 digests on completion, and
the orchestrator reported those to the operator as though they evidenced two
completed reviews. They evidenced two aborted sessions. That is §7 — assert on
reality, never on exit code — failed by an agent that had the rule in its context
digest at the time.

Nothing in the repo asserted the difference between *a file exists and hashes*
and *a verdict exists*, so the error was invisible until a human read the error
events. `phase-5/scripts/envelope-manifest.py` now makes it mechanical and exits
non-zero on this directory. Fixtures for both directions, including the case
where a reviewer greps this repo and its own tool output contains the literal
string `VERDICT: REJECT`, are in `phase-5/scripts/test_envelope_manifest.py`.
